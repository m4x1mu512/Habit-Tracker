# План оптимизации плавности анимаций для Android 8+

Комплексная оптимизация рендеринга, анимаций и распределения памяти в приложении Habit Tracker для достижения стабильных 60 FPS без лагов и задержек даже на устаревших устройствах (Android 8.0/8.1 Oreo, API 26–27).

### User Review & Critical Decisions

> [!IMPORTANT]
> На основе ваших ответов выбрана стратегия автоматической оптимизации рендеринга на уровне архитектуры Jetpack Compose и устранения узких мест во всех анимациях приложения без отключения ключевых функций:
> - **Подтвержденная стратегия**: Автоматическая оптимизация рендеринга и облегчение эффектов.
> - **Область оптимизации**: Все анимации приложения комплексно (свайп вкладок, частицы конфетти, появление/скрытие элементов списков, переходы диалогов).

---

### 1. Overview & Core Concept

- **Что оптимизируется**: Устраняются фазы лишних рекомпозиций (Composition storm) при анимациях перелистывания экранов, исключается нагрузка на сборщик мусора (GC pressure) в физическом движке частиц, оптимизируются списки привычек и переходы диалоговых окон.
- **Целевая среда**: Android 8.0+ (API 26+) на бюджетных процессорах и устройствах с ограниченным объемом оперативной памяти.
- **Ключевой результат**: Стабильная частота обновления кадров (60 FPS), мгновенный отклик на жесты, отсутствие микро-фризов при выполнении привычек и переключении вкладок.

---

### 2. User Experience & Visual Design

- **Свайп страниц (HorizontalPager)**:
  - Плавное скольжение страниц без задержек первого кадра.
  - Сохранение аккуратного эффекта глубины (scale & alpha), но вычисляемого исключительно на этапе отрисовки (Draw phase via GPU), минуя перестройку Compose-дерева.
- **Праздничный салют конфетти**:
  - Сохранение яркой радостной анимации при достижении серии в 7+ дней.
  - Быстрое и лёгкое движение частиц с автоматической адаптацией плотности (уменьшение количества до 40 эффективных частиц на слабых чипсетах).
  - Отсутствие зависания интерфейса в момент нажатия на чекбокс.
- **Списки привычек и карточки**:
  - Стабильные ключи элементов (`key = { habit.id }`) и стабильный тип контента (`contentType`), предотвращающие перерисовку всего списка при обновлении одной привычки.
  - Оптимизированные длительности переходов (180–220 мс) с аппаратным ускорением слоев.

---

### 3. Key Product Decisions & Trade-Offs

- **Decision 1: Перенос чтения смещения пейджера в фазу Draw (`graphicsLayer`)**
  - *Chosen Approach*: Перемещение чтения `pagerState.currentPageOffsetFraction` внутрь лямбды `Modifier.graphicsLayer { ... }`.
  - *Why*: В текущей реализации чтение состояния в теле функции вызывало полную рекомпозицию всех 3 вкладок (`HabitsTabContent`, `StatisticsTabContent`, `ArchiveTabContent`) на **каждом пикселе свайпа** (60–120 раз в секунду). Перенос в `graphicsLayer` полностью изолирует изменения на уровне видеочипа без вызова Compose runtime.
- **Decision 2: Zero-Allocation оптимизация физики конфетти**
  - *Chosen Approach*: Замена постоянного пересоздания списка `List<Particle>` на каждом кадре `withFrameNanos` на плоские примитивные массивы или структуру с пулом объектов и однократной перерисовкой в `Canvas`.
  - *Why*: На Android 8 сборщик мусора ART при массовом создании объектов (85 объектов `Particle` × 60 кадров/сек = более 5000 объектов в секунду) вызывает принудительные паузы GC (Stop-The-World), что приводит к заметному зависанию экрана.
- **Decision 3: Оптимизация анимационных спецификаций (AnimationSpec)**
  - *Chosen Approach*: Использование компактных интерполяторов `tween` и `FastOutSlowInEasing` вместо тяжелых пружинных расчетов с овершутом для списков и карточек.

### 4. Technical Architecture & Data Strategy

```
┌─────────────────────────────────────────────────────────────┐
│                      Jetpack Compose UI                     │
└──────────────────────────────┬──────────────────────────────┘
                               │
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
┌───────────────────────────────┐   ┌─────────────────────────┐
│     HorizontalPager Draw      │   │ Zero-Allocation Confetti│
│   (Zero Recomposition Loop)   │   │  (Optimized Particle)   │
│                               │   │                         │
│ • State read deferred to Draw │   │ • Pre-allocated arrays  │
│ • Hardware graphicsLayer      │   │ • 40 lightweight items  │
│ • No parent recomposition     │   │ • Zero frame GC spikes  │
└───────────────────────────────┘   └─────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│             LazyColumn with Stable Keys & ContentType       │
│ • key = { habit.id }                                        │
│ • Optimized animated visibility (fast tween)                │
└─────────────────────────────────────────────────────────────┘
```

- **Компоненты для доработки**:
  1. `app/src/main/java/com/example/ui/MainScreen.kt`:
     - Рефакторинг `HorizontalPager` и `Box.graphicsLayer`: изоляция фазы Draw.
     - Оптимизация `ConfettiState` и `Particle`: фиксированный пул частиц, исключение аллокаций в кадре анимации.
     - Добавление `key` и оптимизация `items` в `LazyColumn`.
  2. Проверка сборки через `compile_applet` и запуск тестов.
